# 句子资源与短语改造方案（2026-11-13）

状态：已确认（2026-11-13），一次性实施（见第 8 节）。生产已于 2026-11-13 13:05 暂停，上线后恢复。

## 1. 背景

进入短语阶段后暴露出三个结构性问题：

1. **短语一刀切地成为词条。** 主词的短语列表只是一组字符串，没有类型。短语动词、复合名词、习语和整句谚语混在一起，发布后全部成为词条。
2. **谚语装不进“词条 → 义项 → 词性”这套结构。** 整句谚语没有词性，worker 只能硬套成感叹词，审核又要求标 idiom 或 saying，结果卡住。到暂停时，卡住的义项清单工单有 226 张，其中 181 张属于这类，37 张是“只有一个专业义项”的规则冲突。
3. **短语要做的事实照搬单词的那一整套。** 短语的发音只是各个词读音的拼接，复合名词以外的短语也基本没有搭配可言。

另外，例句只是挂在义项下面的一段文字，同一句话不能复用，翻译也要重复做。

## 2. 目标

- 新增一种与词条同级的资源 **Sentence（句子）**，收例句和谚语，可以标来源。
- 短语列表的每一条带**类型**，可以带**所属义项**；用 **id** 指向短语词条或句子。
- 谚语只作为句子存在，不成为词条。
- 短语词条按类型决定要做哪些事实。
- 修正两条自相矛盾的审核规则。

## 3. 数据模型

### 3.1 Sentence 节点

| 字段 | 说明 |
|---|---|
| `id` | 句子 id |
| `text` | 原文 |
| `text_key` | 规范化后的原文，唯一，用于去重 |
| `source` | 自由文本，可以为空。为空表示自造；以后导入的数据可以写书名、电影名等 |
| `created_by`、`created_at` | 创建者和创建时间 |

- 跟词条、义项一样，**节点只表示身份**，不是待审核的内容。`source` 记的是来源，不是要审核的内容，所以作为节点字段，不另设事实。
- **句子不由 worker 直接新建，而是在提交时由服务端创建或复用**，做法跟义项清单创建义项一样：
  - worker 提交例句原文，或在短语列表里提交一条谚语原文。
  - 服务端按 `text_key` 查找，有就复用，没有就创建，再把 id 写回事实里。
- **句子的“类型”在读取时推导，不单独存储：**
  - 某份已发布的短语列表把它作为谚语收录，它就是谚语。
  - 它被某个义项用作例句，它就是例句。
  - 一句话可以同时是两者。

### 3.2 挂在句子上的事实

| 事实 | 内容 | 对谁要求 |
|---|---|---|
| `translation` | `{language, of: "sentence", text}` | 所有被用到的句子，每种服务语言一条。取代现在的 `of: "example"` |
| `sentence_meaning`（新） | `{gloss}`，英文释义 | 只要求谚语 |

### 3.3 例句：义项与句子的关联

- `example` 事实的主体仍然是义项，内容从 `{text}` 改为 `{sentence_id}`。worker 照常提交原文，服务端解析成 id。
- **允许一句话当多个义项、甚至多个词条的例句。** 审核的问题从“这是不是一个好句子”变成“这句话放在这个义项下面合不合适”，沿用现有的例句规则。
- 去重键改成 `sentence_id`：同一义项下同一句话只能出现一次。

### 3.4 短语列表

每一条从字符串改为一个对象：

```json
{"phrases": [
  {"entry_id": "<before long>",              "type": "fixed_phrase"},
  {"entry_id": "<bank account>",             "type": "compound", "sense_id": "<bank 的“银行”义>"},
  {"entry_id": "<bank on>",                  "type": "phrasal_verb"},
  {"entry_id": "<put the cart before the horse>", "type": "idiom"},
  {"sentence_id": "<look before you leap>",  "type": "saying"}
]}
```

- **类型**：`phrasal_verb`（短语动词）、`compound`（复合名词）、`idiom`（习语）、`fixed_phrase`（固定词组，如 at all、in front of）、`saying`（谚语、格言）。
- **只有 `saying` 指向句子，其余类型都指向词条。**
- **`sense_id` 可选**：只在短语明确属于主词的某个义项时才标（如 bank account）。习语、短语动词，以及跟任何义项都无关的条目不标。
- **worker 提交时可以只写原文。** 服务端按原文找到或创建对应的词条（创建时先不进词表）或句子，再把 id 写回事实。
- **整份列表仍然一次性生成、作为一条事实审核**，保持现状。
- **发布后：**
  - 指向词条的条目，进入词表。
  - 指向句子的谚语，生成它的翻译和释义工作项。
  - 一个短语不再被任何已发布的列表作为词条收录时，移出词表。现有逻辑不变。

## 4. 短语词条要做的事实

| 事实 | 短语动词 | 复合名词 | 习语 | 固定词组 |
|---|---|---|---|---|
| 义项清单 | 要 | 要 | 要 | 要 |
| 每个常用义项的翻译、例句 | 要 | 要 | 要 | 要 |
| 同义词（核心义项） | 要 | 要 | 要 | 要 |
| 类别（上位词）、主题 | — | 要 | — | — |
| 发音 | — | — | — | — |
| 搭配 | — | — | — | — |
| 语法 | 继续暂停，以后专门设计“用法格式和能否拆分” | — | — | — |

- 短语词条的类型在读取时推导：取收录它的已发布列表里标的类型。多份列表标得不一样时，按最先发布的那份。
- 已经做好的发音、搭配等事实不删除，只是不再要求，也不计入完成度。

## 5. 审核规则调整

1. **词性只表示语法功能。** 习语、固定词组照常标 verb、noun、adverb 等，审核不得以“应该标为 idiom 或 phrase”为理由驳回。
2. **只有专业义项的词条，主义项算常用。** 义项清单至少要有一个常用义项；一个词条的义项如果全是专业义项（如 China pink、retire hurt），它的主义项不判为放错位置。
3. **短语列表的审核规则增加：**
   - 每条的类型要标对。完整的句子必须标 `saying`，不能作为短语词条收录。
   - 标了所属义项的，要确实属于那个义项；没标的不算错。
4. **谚语的释义和翻译**：按现有翻译规则审核，释义要说清真正的意思和使用场合。

## 6. 公开接口

- 新增 `GET /v1/sentences/{id}`：原文、来源、翻译，谚语还带英文释义。
- 义项的例句改为带 `sentence_id`、原文和翻译，响应格式基本不变，多一个 id 字段。
- 主词的 `phrases` 改为分组展示：
  - 标了所属义项的，放在对应义项下面。
  - 其余的按“短语动词”“习语和固定词组”“复合名词”“谚语”分区。
  - 谚语带英文释义和中文翻译。

| 短语词条 | 15,528 个 | 已做好的事实全部保留。新列表发布后，被标为谚语的条目自动移出词表 |

- 生产端（`../vocnet-producer`）要同步修改：
  - 短语列表的提示词和输出格式：加上类型和所属义项。
  - 新增两种工作项：句子翻译、谚语释义。
  - 例句提交照旧只写原文。

## 9. 一并完成的其他调整（2026-11-13 确认）

1. **同义词/反义词这一格**：核心义项已经有一条发布的上位词时，这一格算完成。worker 仍要把确实存在的同义词和反义词都提交上来；反义词的规则不变。
   依据：同义词通过率 80%、上位词 74%、反义词 96%。卡住的几乎都是没有反义词的义项，worker 交的近义词被判成上位词，这一格因此一直空着。
2. **搭配类型新增三类**：
   - `subject_verb`：the room spins、a stomach grumbles
   - `verb_adjective`：go bankrupt、squash flat、prise open
   - `passive`：tormented by guilt、besieged by reporters、overtaken by sleep

   已发布的搭配不动。
3. **生产端提示词**：派生词的词干拼写有变化时，词干按实际拼法写，再链接到原词条（如 notori- 链接 notorious，tenac- 链接 tenacious）。
4. **导入过滤**：导入主词时：
   - 屈折形式还原成原形，词典词表里单列的除外。
   - 拼写变体合并。
   - 跳过缩写、单个字母和不在词典词表里的词。

   第 2 批导入前必须有。
5. **“撤出词表”接口**：新增 curator 专用接口，把一个主词撤出词表。效果跟短语被列表去掉一样：移出词表，不再生成工作项，也不再公开展示。被已发布的短语列表收录着的短语不能这样撤。以后清理不用再停服务改库。
6. **移出 6 个冷僻词**：用新接口把 fabulate、bereftly、exaltedly、evokingly、genomically、misdemanour 撤出词表。
